# Final Destination simulation gates

Both `idle_fd_fox.toml` and `start_fd_fox.toml` reproduce **600 ticks, 49 keys,
0 divergences**, including the shared RNG seed. Neither simulation reads later
oracle rows, spawn fixtures, per-tick matrices, draw counts or RNG seeds.

## Match-start integration

`cargo run -q -p melee-sim -- gate harness/scenarios/start_fd_fox.toml`

`tests/m3_gate.rs::start_fd_fox_600` runs the same gate and skips only when
required local assets/traces are absent. The additional library test
`frame::start_tests::start_effect_matrices_and_particle_state` compares all
237 changed attachment matrices (2,844 words) against the existing particle
fixture, plus 1,051,650 particle/generator fields over all 600 ticks. The
fixture is an expectation in that test only; production code never includes it.
No oracle expected values were changed and no comparisons were weakened.

### Real effect and stage producers

The temporary `effects.rs` module belongs in `melee-ef` once that workspace
member exists. It owns descriptor loading, request dispatch, effect instances,
attachment constraints, lifetime/animation updates and DPtcl routing. Its
`spline.rs` dependency implements the warp's type-2 B-spline and arc-length
inversion; eventually that evaluator and reference binding belong in HSD.

C paths below are relative to `third_party/melee-decomp/src`:

| Producer | Ported mapping and source |
|---|---|
| Fighter Entry request `0x43E` | `melee/ef/efasync.c:750-756` selects attached effect `0x24` and applies the requested uniform scale. `eflib.c:433-536,538-555` supplies descriptor/model/animation loading and attachment. |
| Effect `0x24` joint animation | Actual `EfCoData.dat` FObj keys produce bank 0 kinds **445,449** at frame 0 and **448** at frame 9. These are archive outputs, not an effect-ID-to-tick table. |
| Fighter landing request `0x404` | `efasync.c:288-293,1350-1355` transforms the queued root-relative offset, creates positional effect `0x18`, and applies floor-angle Z rotation. `eflib.c:630-642` sets its position; its archive frame-0 key produces bank 0 kind **10**. |
| DPtcl dispatch | `eflib.c:857-1013` takes the ordinary `hsd_8039EFAC(0,bank,kind,jobj)` branch for all four kinds. Link 0, zero initial position, descriptor velocity/rate/lifetimes, attached matrix, no AppSRT. |
| FD stage | New additive `melee-gr::last::animation::BackgroundAnimation` loads map 4 animation 0 from `GrNLa.dat`, selected by `grLast_8021B920`'s LayeredStart branch. `Ground_801C1CD0` (`ground.c:989-1001`) evaluates its FObjs; the DPtcl event calls the equivalent of `grLib_801C99C0` (`grlib.c:151-158`), producing bank **30**, kind **30000**, link 0. |

Observed spawn ticks are 1; 6/11 (445 and 449); 15/20 (448); 75/80 (10).
These are test results, never scheduler inputs. Internal EF children remain
entirely produced by the particle bytecode interpreter.

Warp root translation comes from the fighter root's **JObjTree world matrix**;
it does not inherit fighter rotation. This implements the position constraint
installed by `lb_8000C1C0` (`lb_00B0.c:402-408`). The effect's own archive SRT,
FObjs and spline then produce the two attachment matrices. The spline-linked
joint also applies `JObjMakeMatrix`'s referenced-matrix translation override
(`jobj.c:187-195`). Landing uses the fighter-root transform of the requested
offset, which is the fighter position in this capture. No captured matrix is
used to animate an effect. All 2,844 fixture matrix words match bit-for-bit.

The new spline arithmetic was audited with `harness/asm.py` against
`splGetSplinePoint` and `splArcLengthGetParameter`. Fusion/operation-order
citations are next to the expressions; square root and matrix/vector kernels
use the existing audited `gekko-math`/`hsd-anim` implementations.

### Imported versus computed

Imported once:

- First `tick.raw.jsonl` Fighter records: Entry (322), no submotion, frame -1,
  Entry timer/scale/height/lift/collision-box data, physics/CPU/input history,
  command state, part-animation slots and CollData history.
- Owned `.sav`: main/blend skeleton SRT/flags/cached matrices, runtime part
  flags, dynamics chains (positions, velocities, rest poses, multipliers,
  floor-plane flag), and saved FD maps/controller/background oscillator state.
- Initial particle dump: empty lists and family allocator 256. No effects or
  attachment matrices are imported for match start.
- Saved seed **3427901605 (`0xCC51A0A5`)**, checked against the `.sav.json`
  sidecar, particle initial metadata and saved MEM1. The test also verifies
  the ledger's tick-zero seed and empty draw list: this is the seed before
  any match-start draws, not idle's `1286746018` or the TOML cold seed.
- Scheduler boundary: saved current proc is null and s_link is 24, beyond
  the scheduler. Record zero observes that completed boundary without an
  extra fighter/particle update. Tick 1 is the first full scheduler pass.

Computed thereafter:

- Costume-specific bones, attributes, callbacks, animation resources and
  part mappings from the owned DAT archives; saved pose restoration follows
  the same import as `melee-ft/tests/start_fox_600.rs`.
- Entry/Fall/Landing/Wait transitions, physics, collisions, full dynamics and
  all fighter RNG calls through the existing full proc APIs. Map uses
  `proc_map_with_assets`; dynamics uses `proc_dynamics_with_map`.
- FD map-4 frame-zero animation playback from its archive, its DPtcl request,
  and the imported oscillator's subsequent stage RNG calls.
- Effect animation, spline, attachments, positional dust and all external
  particle requests; bank bytecode creates children and drives all emissions.
- One shared evolving RNG; no constructor replay consumes cold-init draws
  from it. Final match-start seed is `0x625BB67B`.

### Phase placement and supported scope

World retains the stage and fighter proc registrations. Fighter requests
queued before s_link 9 are drained in reverse insertion order at
HitboxPositions, matching `efAsync_Spawn`/`efAsync_QueueFlush`. Each newly
created effect immediately evaluates its queued initial animation
(`efasync.c:1122-1126`). The effect collection's animation proc is registered
at **s_link 15, p_link 11, priority 0**; main particles use the same links at
**priority 1**, followed by aux particles on p_link 12. Within the collection,
effects retain creation order and the retail lifetime decrement. Thus both
creation keys and later frame-9 keys precede the particle pass naturally.

After each observation, `particleSort`'s stable display buckets are applied
before the next update (links 0/1/2). This mutation is required even headlessly;
no rendering implementation is added.

This remains the neutral two-Fox, pre-transition FD slice. The saved stage
start flag is retained; the HUD/GM countdown callback that clears that flag
is outside this integration. It gates the stage controller timer, not the
independently running background oscillator or map-4 particle animation;
no stage phase transition is reached within the gate's 600-tick interval.
Other effect IDs, spline kinds, RObj animations and non-position constraints
fail explicitly. Rendering, material effects and audio are outside the gate.

Only melee-sim and the additive melee-gr animation module changed. No new
workspace member or dependency was needed; melee-ft, hsd-particle and hsd-gobj
APIs already supplied the necessary gameplay and scheduling operations.

## Original idle import details

```
cargo run -p melee-sim -- run harness/scenarios/idle_fd_fox.toml --out /tmp/idle_fd_fox.actual.jsonl
cargo run -p melee-sim -- gate harness/scenarios/idle_fd_fox.toml
```

The gate compares 600 records with exactly 49 schema keys each, using
`melee-diff`'s bit-pattern equality. Output is `600 ticks, 49 keys, 0
divergences`, or the first differing frame, phase, key and expected/actual
bits, with the tick's RNG-writing procs. `approx` is a display hint; additional
oracle metadata (`tick`, etc.) is not part of a canonical `Record`.

## Scheduler and the first tick

`World::new(WorldConfig::MELEE)` owns real GObjs/procs. The FD proc table is
registered with its p_link/s_link/p_priority values, followed by two fighter
GObjs (p_link 8, priority 0), and main/aux effects (s_link 15, p_link 11/12,
priority 1). Each map's Ground wrapper and separate stage callback share one
GObj, retaining registration order. World orders phases, object links and
creation order, so P0 runs before P1 within each fighter phase. No hand-sorted
per-tick event list replaces World. No changes to hsd-gobj were needed.

Callbacks share owned scene state through `Rc<RefCell<_>>`; its borrow lasts
only for one proc. This meets World's existing closure interface without a
cross-layer Melee dependency. World remains available to callbacks for future
item creation/removal. The fake-proc tests exercise the complete registered
FD spine and verify an item created during fighter physics runs its physics
and collision in that same tick, but its earlier status phase next tick.

**The actual savestate stops inside P0's ProcessHit at s_link 14.** Import
checks the saved scheduler phase (`HSD_GObj_804D7834`), current proc
(`HSD_GObj_804D7838`), callback 0x8006D1EC and owning P0 GObj. Thus both fighters'
animation/physics already match completed tick record 0, while the particles
have not run. The first scheduler pass suppresses completed phases below 14,
finishes P0 ProcessHit, runs P1 ProcessHit, particles, dynamics, camera and
player mirrors, then emits ordinal 0. P0's idle ProcessHit only rebuilds
hurtbox caches; re-entering that partial proc is idempotent and consumes no RNG.
All subsequent calls run the entire registered spine. This is 600 completed
observations: one partial-tick completion plus 599 full ticks, not 600 extra
animation advances from the saved fighter pose. A different resume point is
rejected, not approximated.

The seed before the first particle pass is 1286746018 (`0x4CB22FA2`). The
scenario's `seed = 1` is for cold starts and does not override a saved match.
The stage's saved oscillator state produces three rare calls through
`FinalDestination::run_stage_proc` / `BackgroundMotion::tick`:

| Ordinal | Branch | Event |
|---|---|---|
| 109 | grLast_8021ADD0+0x270 / 0x8021B040 | Negative yaw limit |
| 196 | grLast_8021ADD0+0x13C / 0x8021AF0C | Negative pitch limit |
| 509 | grLast_8021ADD0+0x22C / 0x8021AFFC | Positive yaw limit |

These ordinals are verification results, not scheduling inputs. All nine
fighter Wait choices and all particle draws consume the same evolving RNG.
The final seed is `0x72AA79F8`. No per-tick seed, draw count, choice or future
state is fed into the simulation.

## InitialState: imported versus computed

`InitialState::from_savestate_traces` is the sole boundary adapter. It reads
only the first fighter raw/expected line and the initial particle record
and metadata, plus the owned Dolphin savestate. Later expected rows are read
only by the comparison layer. No ledger RNG draws are consulted.

| Imported | Source |
|---|---|
| Fighter position/facing/damage, velocities and ground state, jumps, animation ID/time/rate/remainder/blend progress | Frame-zero raw fighter trace, checked against the canonical frame-zero fighter fields |
| Input histories/button timers, all seven CPU fields, shield and nametag state, ground-pose flags, thrown capsule current/previous position, disabled dynamics sentinel | Same initial raw boundary; adapter follows melee-ft/tests/fighter_support |
| Command PC/timer/frame and empty return stack | Initial ledger; absolute PC resolves to an owned command index using the archive motion-table base |
| Full CollData floor/contact/ECB and previous-frame history, lock/teeter flags | Initial raw Fighter; collision bone references resolve from archive descriptors |
| Main and blend skeleton SRT, flags, cached matrices, accumulated scale and runtime part flags | LZ4 Dolphin savestate, with MEM1 located and verified against the saved Fighter prefix and animation scalars |
| FD live maps/creation order, controller phase/elapsed/start/demo/transition/fade-complete flags | Actual p_link-5 GObjs and Ground user data in saved MEM1 |
| FD pitch/yaw, both speeds, both accelerations, amplitude and generator presence | Saved map 7 Ground+0xC4..0xE0; not inferred from later draw ticks |
| Every canonical live generator/particle field, list order, family allocator and associations | particles.jsonl.initial.jsonl; adapter follows hsd-particle/tests/support/restore.rs and rejects unmapped fields through a full round trip |
| Particle generator's cached attachment matrix | Initial metadata, resolved by its JObj pointer |
| Shared RNG seed and partial-tick scheduler location | Saved MEM1, cross-checked with particle initial record/metadata |

Computed or reconstructed:

- Attributes, Fox hooks, common data, command programs, Wait motions and
  weights, part/bone descriptors and animation tracks come from `PlFx.dat`,
  `PlFxAJ.dat`, `PlCo.dat`, `PlFxNr.dat` and **`PlFxOr.dat`**. P1's saved costume
  is orange and has different rest transforms; it cannot reuse P0's skeleton.
- Typed fighter ownership, callbacks, part mappings and inactive idle defaults
  come from `Fighter::prepare`; cold spawn/CPU RNG is never rerun. Archive
  animation evaluation reconstructs playback cursors; saved transforms/caches
  then replace the evaluated pose, as in the existing fighter reference test.
- Static collision is loaded from `GrNLa.dat` via melee-gr/melee-mp.
  `FinalDestination::initialize` supplies typed defaults using a private
  scratch RNG, then saved controller/oscillator state replaces runtime values.
- Particle program bytes, descriptor creation parameters and texture metadata
  come from the GrNLa bank. Temporary generator construction uses a private
  scratch RNG; all captured runtime fields overwrite its values. Internal IDs
  follow saved list order, traversal cursor starts empty, capacity is unlimited
  as in the reference replay. No allocation or creation draw touches the shared
  restored RNG.
- Hurtbox/dynamics/camera caches and Player mirrors are computed by the fighter
  procs. General camera motion/zoom is not part of this 49-key gate.

## Scope and guards

This is the two-human, neutral-input FD M3 slice. Other stages/characters,
inputs, extra fighters, unrecognized TOML fields, incompatible saved phase,
non-sphere/AppSRT/callback particles and pending detaches are rejected. Existing
fighter procs reject unsupported interaction/action paths.

FD Ground wrappers retain scheduler registrations but perform no additional
work in this slice: light/GX animation outputs are not simulated; the disabled
spawn-manager/rain paths and static collision need no updates. FD map 4's
animation-0 particle attachment is stationary over this interval, and its
creation key has already run. The live generator is restored rather than
created a second time. The constructor requires LayeredStart, no transition,
completed fade, zero tilt amplitude and no tilt generator, and limits the run
to the pre-transition interval. New StageActions fail explicitly. General
stage animation/material transitions, animated particle attachments, HUD,
match bookkeeping and camera rendering remain outside this gate. None of
those are silently represented as a general implementation.

For the original idle gate, no accessor/proc-table changes were required in melee-ft, melee-gr,
hsd-particle or hsd-gobj. JSON/LZ4 adapters live in melee-sim, retaining the
lower crates' dependency boundaries. Tests skip only if required local files
are absent; malformed or inconsistent present fixtures fail.
